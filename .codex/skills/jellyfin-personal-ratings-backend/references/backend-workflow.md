# 后端工作流

## 实现优先级

1. 先让插件被 Jellyfin 识别
2. 再让数据库能初始化
3. 再完成单条评分查询、设置、清分
4. 再补分页查询
5. 再补批量操作
6. 最后补物理删除和审计

## 代码规范

1. 先最小实现，不要过度设计
2. C# 局部变量显式类型，不使用 `var`
3. Controller 不承载业务逻辑
4. Repository 不跨层关心 UI
5. 关键 public 方法加 XML 注释
6. 关键异常必须记录日志
7. 批量操作和物理删除必须记录日志

## 风险处理

- 不要假设 Jellyfin 10.11 的 API 可以直接用于 10.10.7
- 不要伪造未知 API
- 不确定的媒体删除、Item 解析或路径能力，统一隔离在解析器或服务层
- 如果某个 API 只能猜测存在，要把它降级成 TODO，而不是写成“已知可用”

## 验证方式

- 有 `.csproj` 后优先执行定向 `dotnet build`
- 如果只有局部模块，优先做最小范围编译或静态检查
- 改动涉及 SQL 时，至少核对表结构、唯一约束、索引和分页字段
- 改动涉及权限时，至少核对普通用户与管理员能力边界

## 异常场景清单

1. 评分范围非法
2. `ItemId` 不存在
3. 数据库初始化失败
4. 当前用户为空
5. 普通用户调用管理员接口
6. 删除媒体失败
7. 文件已不存在
