# 项目背景与约束

## 一、当前运行环境

- Jellyfin 版本：**10.10.7**
- 构建版本：**260326**
- 运行方式：**Docker**
- 镜像：**nyanmisaka/jellyfin**
- 使用场景：个人拍摄素材库管理
- 主要客户端目标：**Jellyfin Web 端**

## 二、业务背景

用户已经在 Jellyfin 中正确识别并解析好了自己的拍摄素材库。
现有素材封面、媒体识别、基础播放都不是本项目关注点。

当前的痛点是：

1. Jellyfin 原生 Favorite 只有“收藏 / 不收藏”两级，不够细。
2. 收藏内容越来越多后，无法快速区分“非常喜欢 / 一般 / 不喜欢 / 待清理”。
3. 需要一种更适合素材库管理的机制，而不仅仅是传统影音库收藏。

## 三、插件目标

开发一个自定义插件，提供：

1. 私有评分：1~5 分。
2. 按分数分类查看。
3. 支持筛选与分页。
4. 支持批量管理。
5. 支持待删除标记与物理删除。

## 四、明确不做的事情

第一版不做以下内容：

1. 不做 Android / iOS / TV 原生客户端 UI。
2. 不做第三方评分站点联动。
3. 不做推荐算法。
4. 不做公开评分，不与社区评分混用。
5. 不以 Jellyfin 原生 Favorite 为核心数据源。

## 五、核心产品规则

### 1. 评分规则

- 评分范围：`0~5`
- `0` 表示未评分
- `1` 表示最差
- `5` 表示最优

### 2. 用户隔离

评分按 **Jellyfin 用户维度** 存储。
即同一个视频对不同 Jellyfin 用户可以有不同评分。

### 3. 收藏联动

第一版默认 **不强依赖 Favorite**。
但可以预留一个配置项：

- 当评分 >= 4 时自动同步为 Favorite

### 4. 删除规则

删除必须分两级：

- 待删除标记
- 真正物理删除

其中：

- 普通用户：不能物理删除
- 管理员：可以物理删除

### 5. 客户端范围

第一版只保证 **Web 端** 可用。

## 六、技术约束

1. 使用 **C# / .NET**。
2. 使用 Jellyfin 官方插件模板风格组织代码。
3. 第一版只适配 **Jellyfin 10.10.7**。
4. 使用 **SQLite** 存储评分数据，不使用 JSON 作为主数据源。
5. 不在代码中硬编码 Docker/Linux 路径。
6. 所有路径通过 Jellyfin 提供的应用路径接口获取。

## 七、工程约束

1. 先做最小可运行版本。
2. 先实现后端，再补前端体验。
3. 先保证详情页打分和管理页查询，再做复杂批量操作。
4. 先支持视频类条目，后续再扩展到其他媒体类型。

## 八、需要 Codex 避免的常见问题

1. 不要伪造 Jellyfin API。
2. 不要把所有逻辑塞进 Controller。
3. 不要把数据库逻辑直接写在 UI 脚本里。
4. 不要一上来做很重的前端工程。
5. 不要假设 Jellyfin 10.11 的 API 一定和 10.10.7 完全一致。
