# 技术设计初稿

## 一、总体设计

推荐实现方式：

- **后端插件**：负责数据存储、权限校验、查询与删除接口
- **Web 前端**：负责详情页评分 UI 与评分管理页 UI

不建议只做前端脚本，因为该项目需要：

- 用户评分持久化
- 条件筛选
- 分页查询
- 批量操作
- 管理员删除
- 审计日志

这些都更适合在后端插件中实现。

## 三、数据存储设计

主存储使用 **SQLite**。

原因：

1. 易部署
2. 不引入额外数据库依赖
3. 查询/筛选/分页方便
4. 适合中小规模个人素材库

### 表 1：user_item_ratings

```sql
CREATE TABLE IF NOT EXISTS user_item_ratings (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id TEXT NOT NULL,
    item_id TEXT NOT NULL,
    score INTEGER NOT NULL DEFAULT 0,
    is_pending_delete INTEGER NOT NULL DEFAULT 0,
    last_played_at TEXT NULL,
    rated_at TEXT NULL,
    updated_at TEXT NOT NULL,
    created_at TEXT NOT NULL,
    UNIQUE(user_id, item_id)
);
```

索引：

```sql
CREATE INDEX IF NOT EXISTS idx_ratings_user_score ON user_item_ratings(user_id, score);
CREATE INDEX IF NOT EXISTS idx_ratings_user_pending ON user_item_ratings(user_id, is_pending_delete);
CREATE INDEX IF NOT EXISTS idx_ratings_user_updated ON user_item_ratings(user_id, updated_at DESC);
```

### 表 2：delete_audit_logs

```sql
CREATE TABLE IF NOT EXISTS delete_audit_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    operator_user_id TEXT NOT NULL,
    item_id TEXT NOT NULL,
    item_name TEXT NULL,
    action TEXT NOT NULL,
    result TEXT NOT NULL,
    message TEXT NULL,
    created_at TEXT NOT NULL
);
```

## 五、API 设计

统一前缀：

`/Plugins/PersonalRatings`

### 1. 评分接口

#### GET /rating

查询当前用户某个条目的评分。

参数：

- `itemId`

#### POST /rating

设置评分。

请求体：

```json
{
  "itemId": "12345",
  "score": 5
}
```

#### DELETE /rating

清除评分。

参数：

- `itemId`

### 2. 列表查询接口

#### POST /ratings/query

请求体示例：

```json
{
  "score": 5,
  "isPlayed": true,
  "isPendingDelete": false,
  "libraryIds": [],
  "mediaTypes": [],
  "keyword": "",
  "sortBy": "updatedAt",
  "sortOrder": "desc",
  "pageNumber": 1,
  "pageSize": 50
}
```

### 3. 批量接口

#### POST /ratings/batch/set-score

```json
{
  "itemIds": ["1", "2", "3"],
  "score": 4
}
```

#### POST /ratings/batch/clear-score

#### POST /ratings/batch/set-pending-delete

#### POST /ratings/batch/unset-pending-delete

#### POST /ratings/batch/delete-physical

## 六、服务层设计

### 1. IRatingRepository

职责：

- 查询单条评分
- 插入/更新评分
- 条件分页查询
- 批量更新评分
- 批量设置待删除状态

### 2. IRatingService

职责：

- 校验评分范围
- 设置评分
- 清除评分
- 查询评分
- 查询分页列表
- 管理 Favorite 同步

### 3. IDeletionService

职责：

- 校验管理员权限
- 校验媒体条目可删除性
- 执行物理删除
- 写入审计日志

### 4. IJellyfinItemResolver

职责：

- 根据 `ItemId` 解析 Jellyfin 媒体条目
- 获取名称、类型、路径、播放信息等

## 七、前端设计

### A. 详情页脚本

文件：`details-rating.js`

职责：

- 在详情页插入评分组件
- 加载当前评分
- 提交评分
- 清除评分
- 切换待删除

### B. 管理页

文件：

- `manage-page.html`
- `manage-page.js`
- `manage-page.css`

职责：

- 展示筛选栏
- 展示分页列表
- 支持多选
- 支持批量操作

## 八、权限设计

### 普通用户

允许：

- 给自己的视图打分
- 清除自己的评分
- 查看自己的评分列表
- 标记/取消待删除

### 管理员

额外允许：

- 物理删除媒体项
- 查看删除审计日志（可选）

## 九、异常处理

必须覆盖：

1. 评分范围非法
2. `ItemId` 不存在
3. 数据库初始化失败
4. 当前用户为空
5. 普通用户调用管理员接口
6. 删除媒体失败
7. 文件已不存在

## 十、日志策略

建议：

- 普通查询不要刷太多日志
- 批量操作必须记录
- 物理删除必须记录
- 关键异常必须记录
